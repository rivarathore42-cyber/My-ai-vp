# Galaxy AI Engine v7.0

A private assistant: 20 agents (math, knowledge, code, creative writing, translation, data, memory, voice and more), a
chat page with a voice orb, and file and location sharing. It deploys to Render.com as a Docker web service, and the same
page runs as an Android app through the WebView wrapper in `android/`.

## Deploy on Render

1. Push this repository to GitHub.
2. In Render, choose **New > Blueprint** and select the repository. Render reads `render.yaml` and builds the `Dockerfile`.
3. Open the service URL. The page opens straight into the assistant; there is no pairing step.

Render sets `$PORT`; the server listens on it on all interfaces. The health check is `/health`.

## Read before you share the link

- Anyone who can reach the URL can chat as the owner, and the answers draw on the owner's notes. Keep the link private, or
  add access control before you share it. Admin routes (memory, tuning, tokens) need the operator token; the chat does not.
- The page sends your location only when you tap 📍 or turn on Live, and it stops when you turn Live off. The camera opens
  only when you tap 📷. Files are checked by their content (an image or a PDF); their text is not read.
- A free instance has limited memory (check Render's current plan list), sleeps when idle, and has no persistent disk. A
  restart or a sleep clears the database, so conversations and notes are lost then.
- The local model is off by default (`GALAXY_SKIP_LLM=1`). The engine runs in heuristics mode, and all 20 agents still
  answer, with a plain reason whenever they cannot.
- Hosting terms (payment requirements, limits) change. Check the Render dashboard.

## Permissions

The page asks for each permission with a short card in Hindi and English, and then the browser's own prompt:

- **Microphone**: for "Hey Galaxy" voice commands. Audio is processed on the device.
- **Location**: for 📍 (one fix) and Live (until you stop it).
- **Camera and files**: 📷 opens the camera through the phone; 📎 opens the file picker.

If a permission is denied, the page says so and keeps working with text. Location and the microphone need https.

The Android wrapper (`android/`) answers the same requests with Android's own permissions. See `android/README.md`.

## Settings

| Name | Default | What it does |
|---|---|---|
| `GALAXY_OWNER_ID` | `owner` | The user id every visitor's session acts as. |
| `GALAXY_API_TOKEN` | generated by Render | The operator token for the admin routes. Chatting never needs it. |
| `GALAXY_SKIP_LLM` | `1` | `1` runs heuristics only; `0` loads the local model (needs a build with `INSTALL_LLM=1`). |
| `GALAXY_DB` | `galaxy_memory.db` | Where the SQLite database lives. |

## Run locally

```
pip install -r requirements.txt
python run.py
```

Open http://127.0.0.1:8000/. Without `PORT` set, the server stays on loopback.

## Tests

```
python3 tests/test_v6.py      # the Python checks (about 1,050), including sections Y and AB
node tests/js/app_logic.test.js
```

## Voice (Hey Galaxy)

Voice Wake-Up runs offline in the browser with Vosk. It needs `vendor/vosk.js` and two model archives, fetched at build time
only when you set the build argument `FETCH_VOICE=1`. Check the sources in `scripts/fetch_voice_assets.py` first. Without
them, the page shows voice as unavailable and nothing else changes. Audio never leaves the device.
